静态建站的思路是：**内容在构建时一次性拉取，烘焙成纯静态页面**。线上没有数据库和服务端，换来的是速度、安全和近乎零维护。

## 结构

```
编辑者 → CMS 后台 → 内容变更
                    ↓ (Git 提交 或 Webhook)
        托管平台触发构建 (astro build)
                    ↓
  纯静态 HTML/CSS/JS → CDN 全球分发
```

## 代价与收益

代价是改内容后要等 1–3 分钟重新构建。收益是：

1. **快** —— 无数据库查询，页面即文件；
2. **安全** —— 没有服务端就没有可攻击的入口；
3. **免运维** —— 托管平台负责构建和分发；
4. **版本可控** —— 内容在 Git 仓库里，天然有历史记录和回滚。

## 选型思路

- **Git-based CMS**（Keystatic、Decap）：内容存仓库里的 Markdown，适合 1–3 个编辑者，最省事；
- **托管 SaaS**（Sanity、Contentful）：内容存厂商云端，适合多编辑者、结构化内容多的场景；
- **自托管**（Strapi、Payload）：需要一台服务器，与"纯静态零运维"的目标冲突。
